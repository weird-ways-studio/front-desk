# front-desk

Off-box service that lets studio agents ask for narrow, short-lived access, approved by Ben's passkey on his phone. Card C5c-1 ebd61173, epic 46fc7b61. Design: `~/studio/studio-os/docs/specifications/face-id-access/C4-SPIKE.md`.

## Rules for agents working here

- This repo is PUBLIC (Ben, 2026-10-25). No secrets, hostnames of the live front desk, or account IDs in code or docs. The pre-commit hook refuses the known ones (`~/studio/studio-os/scripts/public_repo_guard.py`, list in private studio-os `hooks/public-repo-deny/front-desk.txt`; add new IDs there, never here).
- `main` deploys to Cloudflare automatically and only through Ben's approved pull request (ruleset `protect-main`). Never ask for or use a bypass.
- Installs and the local runtime run through `~/studio/studio-os/scripts/sandbox-run` (third-party code).
- Every safeguard gets a test that fails when the safeguard is removed (instruction.control-must-refuse-unsafe-case).

## Where behavior lives

- `src/index.ts` -- Worker entry (named by `main` in `wrangler.jsonc`); forwards every request to the one Durable Object `FrontDesk`.
- `src/agent.ts` -- recognises the c-box agent from its verified Access service-token ticket.
- `src/routes.ts` -- HTTP routes. `src/desk.ts` -- grant, approval, collect and log rules. `src/jobs.ts` -- the fixed job list. `src/page.ts` -- phone pages.
- Job modes and the agents' menu (card ae6147e4, 4a-1): each job in `src/jobs.ts` has `mode` (tap today; run and key are not built) and `menu` text. `GET /menu` (agent login; `menu()` in `src/jobs.ts`, route in `src/routes.ts`) is generated from JOBS -- there is no hand-written copy; `node scripts/agent.mjs menu <desk-url>` prints it. A stored grant for a job no longer in JOBS (the retired `cf.token.zone.read`) is refused as `job_retired` in `Desk.grant()`.
- Read jobs `cf.zone.read`, `cf.dns.list`, `cf.audit.read`: at Ben's tap the vault (`read()` in `vault/src/vault.ts`) reads with short keys of a fixed policy and hands the agent only the answer. Their request and collect need the c-box signature (`signed` in `src/jobs.ts`).
- The vault's short keys (`withKey()`): each is recorded in vault storage `helpers` before it is made and until its delete is confirmed; `sweepHelpers()` runs at every approved Cloudflare tap; the nightly count lists leftovers as `cleanup` (never `unexpected`, so `cf.token.accept` cannot adopt one).
- Keeping a Cloudflare key the front desk did not make (card 2c19a923, Build R): job `cf.token.accept` stores it in vault `master.exceptions` with the scope Ben's screen showed (`scopeWords()` in `vault/src/vault.ts`), only by his tap. The vault refuses a key whose live scope differs from that screen, or that is over the ceiling (`overCeiling()`: read-only groups, this account and its zones, nothing touching keys, unreadable fails); the desk never offers such a key (`src/desk.ts` request). The nightly count's `widened()` alarms when a kept key changes or exceeds the ceiling, or when the headcount key is no longer exactly one `Account API Tokens Read` group (by the id recorded at setup, `HeadcountKey.group_id`) on this account. Kept-key scopes include group ids, the address condition, not-before and expiry, so any change alarms. A headcount key made before Build R has no recorded id: the night reports `headcount_key_needs_setup` until Ben re-runs `cf.token.headcount.setup`.
- `src/cboxkey.ts` -- checks the c-box signature on key requests and collects; `scripts/agent.mjs` -- the c-box side (makes the key, signs requests). No libraries in either.
- `vault/` -- the second Worker `front-desk-vault`: sealed master key and the jobs that use it. No libraries allowed (enforced by `test/vault.test.ts`). The front desk reaches it only through the service binding `VAULT` declared in `wrangler.jsonc`; the RPC methods live in `vault/src/index.ts`, the rules in `vault/src/vault.ts`, the sealing in `vault/src/seal.ts`, its one-time setup page in `vault/src/setup.ts`.
- The vault's own check of Ben's tap (card bb86abf0): `vault.run({grant, assertion, prf})` runs a job only if `assertion` is Ben's passkey answer for exactly that grant -- `checkSigned()` in `vault/src/approval.ts` recomputes the grant hash and checks the answer with `vault/src/passkey.ts`, a verbatim copy of the Observatory recorder's verifier (source and commit in its header; the pin `PASSKEY_PIN` is the recorder's, public values only). Then `admit()` (storage calls only) refuses a grant already in vault storage `used` (`already_used`: it may have run) or past `expires_at` + 5 min (`expired`: too old, which does NOT prove it never ran, since ids are pruned at that same boundary), prunes `used`, and records the id. The codes `wrong_shape`, `no_pin`, `bad_grant`, `bad_assertion` are raised before admission: this call started nothing. The desk (`approve()` in `src/desk.ts`) asks `approvalApi()` first (another version: `wrong_shape`, nothing sent), sends the grant fields and `assertionOf()`, and maps the exact code with `vaultStage()`; `src/jobs.ts` `stageWords()` turns it into one of four sentences for Ben (an old desk during a deploy keeps its unchanged `notDone()` words). An old-shape call `run(job, params, prf)` arrives with extra arguments (`run(req, ...rest)` in `vault/src/index.ts`) and is refused `wrong_shape`. Verdicts shared with the recorder: `test/fixtures/passkey-vectors.json` (made once by `test/fixtures/make-passkey-vectors.ts`, verdicts from the recorder's own code); when Ben's passkey changes, the pin changes here and in the Observatory. Tests: `test/vaultcheck.test.ts`, real workerd `test/approval.workerd.test.ts`.
- Nightly headcount (card C5c-2 3baea7cc): Cloudflare runs `scheduled()` in `src/index.ts` on the cron in `wrangler.jsonc` "triggers" -- nothing in the routes calls it.
